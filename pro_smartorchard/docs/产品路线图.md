# 苹果种植园管理系统 — 产品路线图

> 版本：v1.0 | 日期：2026-05-20 | 编制：路径（Roadie）  
> 适用周期：2026 Q3 — 2027 Q4

---

## 一、迭代策略总览

### 分阶段逻辑

采用 **"核心闭环先行 → 专业纵深突破 → 数据智能升级"** 三阶段递进策略：

| 阶段 | 代号 | 主题 | 核心目标 | 预估周期 |
|------|------|------|---------|---------|
| Phase 1 | 春播 | 核心闭环 · 能用 | P0 功能全部落地，三大角色核心操作跑通，移动端极简体验达到"离线可用" | 4 个月（16 周） |
| Phase 2 | 夏耘 | 专业纵深 · 好用 | P1 功能全量交付，农资全链路闭环，采收季前上线采收与追溯 | 4.5 个月（18 周） |
| Phase 3 | 秋收 | 数据智能 · 聪明 | P2 功能深化，数据大屏实景中心上线，物候期模型逐基地微调 | 3.5 个月（14 周） |

**总工期估算：12 个月（48 周），约 72 人月**

### 关键设计原则

1. **移动端不后置**：Phase 1 即交付移动端核心操作（农事记录、巡园打卡、预警推送），确保一线用户体验
2. **MVP 先行**：每个功能模块先做最简可用版本，再在后续阶段增量增强
3. **采收季倒排**：苹果采收窗口（8-10 月），采收管理须在 7 月底前上线
4. **数据大屏两步走**：Phase 1 先做基础经营看板，Phase 3 再做实景中心沉浸式大屏
5. **物候期模型渐进**：Phase 1 用通用版，Phase 3 逐基地微调参数

## 三、详细路线图

### Phase 1 — 春播（核心闭环 · 能用）

**时间窗口**：2026 Q3（7 月 — 10 月）| **工期**：16 周 | **人力**：约 24 人月

#### 迭代拆分

| 迭代 | 周期 | 目标 | 交付物 |
|------|------|------|--------|
| Sprint 1-2 | W1-W4 | 基础架构成型 | 三端脚手架、统一设计系统、离线同步引擎原型、用户/角色权限体系 |
| Sprint 3-4 | W5-W8 | 基础数据+农事核心 | 企业/基地/地块 CRUD、农事任务创建→分配→执行→反馈闭环、PC+移动端联动 |
| Sprint 5-6 | W9-W12 | 巡园+预警+农资查询 | 巡园打卡（移动端拍照+定位）、预警设置与推送（极光/FCM）、农资库存查询（移动端离线缓存） |
| Sprint 7-8 | W13-W16 | 联调+内测+上线 | 三端数据同步联调、弱网/离线场景压测、首轮内测（2-3 家基地）、Bug 修复与优化 |

#### 里程碑

| 里程碑 | 日期 | 标志 |
|--------|------|------|
| M1-架构冻结 | W4 末 | 三端技术选型确认、API 契约签署、离线同步方案评审通过 |
| M2-核心闭环可用 | W8 末 | 农事任务从创建到反馈全链路跑通，PC+移动端联调通过 |
| M3-Phase 1 上线 | W16 末 | P0 功能全量交付，2-3 家基地内测通过，NPS ≥ 30 |

#### 功能清单与依赖

```
企业/基地/地块管理 ─────┐
                        ├─→ 农事任务闭环（依赖基础数据）
权限体系 ───────────────┘
                        
移动端离线引擎 ──→ 巡园打卡（依赖离线同步）
                ──→ 预警推送（依赖消息通道）
                ──→ 农资库存查询（依赖离线缓存）
```

#### Phase 1 交付标准（Definition of Done）

- [ ] PC 端：8 大模块入口可见，P0 功能 100% 可用
- [ ] 移动端：首页/服务/地块/我的 四区可用，核心操作 ≤3 步
- [ ] 离线：山区弱网（2G/3G）下农事记录不丢失，恢复后自动同步
- [ ] 数据同步：三端数据一致性 ≥ 99.5%
- [ ] 性能：移动端冷启动 ≤2s，核心操作响应 ≤500ms

**时间窗口**：2026 Q4 — 2027 Q1（11 月 — 次年 2 月）| **工期**：18 周 | **人力**：约 30 人月

#### 迭代拆分

| 迭代 | 周期 | 目标 | 交付物 |
|------|------|------|--------|
| Sprint 9-10 | W17-W20 | 农事增强+数据看板 | 农事记录快速录入（拍照识别+语音）、经营数据看板基础版（产量/成本/效率三大指标） |

| Sprint 13-14 | W25-W28 | 追溯+采收 | 产品追溯码管理与数字履历、采收计划/记录/采后处理（⚠️ 须在采收季前上线） |
| Sprint 15-16 | W29-W34 | 体验打磨+灰度 | 移动端体验优化（大字大按钮、手势优化）、灰度发布（10 家基地）、性能调优 |

#### 里程碑

| 里程碑 | 日期 | 标志 |
|--------|------|------|
| M4-看板可用 | W20 末 | 经营数据看板 MVP 上线，管理者可看核心指标 |
| M5-农资闭环 | W24 末 | 农资采购→退货→使用→库存全链路跑通 |
| M6-采收就绪 | W28 末 | 采收管理模块上线，追溯码可生成扫码 ⚠️ 关键里程碑 |
| M7-Phase 2 上线 | W34 末 | P1 功能全量交付，10 家基地灰度验证通过 |

#### 功能清单与依赖

```
农事记录快速录入 ──→ 依赖 Phase 1 农事任务闭环
经营数据看板 ──────→ 依赖 Phase 1 基础数据积累
设备状态监控 ──────→ 依赖 IoT 设备接入标准（外部依赖⚠️）
农资采购退货 ──────→ 依赖 Phase 1 农资库存查询
农资使用+库存联动 ─→ 依赖农资采购退货
产品追溯 ─────────→ 依赖采收管理（追溯码绑定采收批次）
采收管理 ─────────→ 依赖农事记录（采收属于特殊农事）
```

#### ⚠️ 关键时间约束

- **采收管理**：苹果采收窗口为 8-10 月，Phase 2 须在 W28（约 2027 年 2 月）前完成开发，确保 2027 年采收季可用
- **设备接入**：7 类设备工控协议各异，建议 Phase 1 即启动设备对接调研，Phase 2 并行开发

## 七、风险评估

### Phase 1 风险

| 风险 | 概率 | 影响 | 缓解措施 |

## 八、利益相关者沟通要点

### 8.1 高管版 — 聚焦战略对齐与业务影响

**核心信息**：我们抓住了政策窗口期，用 12 个月完成从 0 到 1，在苹果产业数字化领域建立先发优势。

| 要点 | 说明 |
|------|------|
| 战略卡位 | 2024-2028 政策窗口，苹果垂直领域无龙头，先发即壁垒 |
| 交付节奏 | 三步走：4 个月能用 → 4.5 个月好用 → 3.5 个月聪明 |
| 关键决策 | ① 是否追加 IoT 设备预算 ② 追溯体系是否对接国家平台 ③ 灰度客户名单确认 |
| 业务指标 | Phase 1 末：2-3 家基地内测；Phase 2 末：10 家灰度；Phase 3 末：20+ 运营中 |
| 投入产出 | 72 人月投入，预期 20+ 基地订阅，单基地年费覆盖开发成本 |

### 8.2 工程版 — 聚焦技术细节、时间线、依赖

**核心信息**：离线同步和三端一致性是技术硬骨头，设备接入是外部依赖风险点。

| 要点 | 说明 |
|------|------|
| 技术红线 | 离线不丢数据、操作 ≤3 步、三端实时同步 — 不可妥协 |
| 架构关键决策 | 离线同步引擎选型（CRDT vs 增量快照）、统一接入层设计、消息推送架构 |
| 外部依赖 | IoT 设备协议对接（7 类）、气象数据源、追溯码编码标准 |
| 里程碑节奏 | M1 架构冻结 → M2 核心闭环 → M3 Phase1 上线 → M6 采收就绪 → M10 全量上线 |
| 技术债管理 | 每迭代预留 10% 工时还技术债，Phase 3 集中偿还 |
