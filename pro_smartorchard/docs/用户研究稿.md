# 苹果种植园内部管理系统 — 用户研究综合分析报告

---

## 一、三类用户画像

### 1. 企业管理者

| 维度 | 描述 |
|------|------|
| **角色定位** | 企业决策层（老板/总经理/副总），拥有多个基地，关注全局经营绩效与战略方向 |
| **典型特征** | 年龄40-55岁，对数字化态度"结果导向"——能用就行，不看过程；习惯看报表、开会、电话调度 |
| **核心诉求** | ① 经营数据一目了然（产量、成本、收益、同比环比）；② 风险可控（预警信息不漏、异常能追溯）；③ 跨基地对比与决策支撑（哪个基地表现好、哪个地块需投入） |
| **使用场景** | 办公室电脑查看经营日报/周报；会议室投屏数据大屏汇报；出差途中手机看关键指标和预警推送 |
| **技术接受度** | 低→中。不排斥但不愿花时间学习复杂操作；对数据大屏的"视觉冲击"有好感（向投资者/政府展示时体面）；手机端只接受"打开就能看到核心信息" |
| **隐性诉求** | 需要系统能"讲故事"——向银行、政府、合作伙伴展示企业现代化程度；担心数据泄露但又不理解权限管理细节 |
| **典型一天** | 上午：看大屏概览/手机推送的预警 → 电话追问基地负责人；下午：电脑端看月度经营分析报表 → 审批大额农资采购；晚间：手机扫一眼当日巡园完成率 |

---

### 2. 基地管理者

| 维度 | 描述 |
|------|------|
| **角色定位** | 单一基地的运营负责人（场长/基地经理），承上启下——对上汇报、对下调度，是系统的"核心重度用户" |
| **典型特征** | 年龄35-50岁，多从技术骨干晋升，懂种植但管理手段传统（微信群+Excel+电话+手写本）；每日工作碎片化，频繁在办公室与田间切换 |
| **核心诉求** | ① 农事排程与人员调度效率（每天安排几十号人干什么活、在哪个地块）；② 农资库存与消耗把控（化肥农药不浪费、不缺货）；③ 设备运转状态监控（灌溉、气象站、水肥一体化是否正常）；④ 向上汇报便捷（一键生成周报、产量预估） |
| **使用场景** | 早晨办公室电脑排布当日农事计划；白天田间手机查看设备状态/处理预警/审批农资申领；晚上手机看当日执行完成率、写工作日志 |
| **技术接受度** | 中→高。是系统最可能深度使用的角色，但痛点在于"如果系统比我微信群+电话还慢，我就不用了"；对移动端依赖极高，电脑端用于复杂报表和计划编排 |
| **隐性诉求** | 管理压力——人员流动大、季节性用工难调度；需要系统帮自己"免责"（农事记录留痕，出了问题可追溯）；想降低对"老经验员工"的依赖 |
| **典型一天** | 06:00 手机看气象/预警 → 07:00 电脑排当日农事 → 08:00-12:00 田间巡园+手机处理农资申请 → 13:00 手机看巡园打卡情况 → 14:00-17:00 继续田间+处理设备异常 → 18:00 电脑看当日执行报表/补充记录 |

---

### 3. 地块负责者（一线人员）

| 维度 | 描述 |
|------|------|
| **角色定位** | 一线执行者（地块管理员/技术员/季节工），负责具体地块的日常农事执行与巡查 |
| **典型特征** | 年龄25-55岁跨度大；季节工流动性极高，长期工相对稳定但年龄偏大；手机是唯一工作设备，很多不会用电脑；网络环境不稳定（山区果园信号弱） |
| **核心诉求** | ① 今天我要干什么、在哪个地块（任务清单清晰）；② 农事记录操作简单（拍照+选选项，不要打字多）；③ 巡园打卡不折腾（定位自动、不重复操作）；④ 农资使用能快速记录（用了什么、用了多少） |
| **使用场景** | 早上看手机任务列表；田间干活时拍照记录农事/标记异常；巡园时GPS打卡+拍病虫害照片；收工前确认今日任务完成 |
| **技术接受度** | 低。关键障碍：① 手机存储不够/网不好；② 字小看不清；③ 操作步骤多就放弃；④ 不喜欢"被监控"的感觉但能接受"任务驱动"型交互 |
| **隐性诉求** | 计件/绩效考核的公平性——干了多少活、巡了多少园需要被准确记录；害怕"记错"被扣钱；想要"别人也能看到我干了活"的证明 |
| **典型一天** | 06:30 手机看今日任务 → 07:00-12:00 按任务执行（记农事、巡园打卡）→ 12:00 提交农资使用记录 → 14:00-17:00 继续任务 → 17:30 确认完成/提交异常反馈 |

## 二、用户旅程地图

### 企业管理者旅程

```
阶段        触点                          行为                    痛点                          情绪
─────────────────────────────────────────────────────────────────────────────────────────────────────────
信息获取    大屏概览/手机推送              查看经营数据、预警       数据维度多抓不住重点          😐 → 😟
            经营分析报表                   看同比环比趋势           报表生成慢、口径不一致        😐
决策判断    跨基地对比/投入产出分析         做投入决策              缺少智能建议只有数据          😐 → 😕
            预警处理                       电话确认异常            预警信息不够精准、误报多      😤
审批执行    采购审批/预算审批               电脑端审批              审批流程长、移动端不便        😐
结果追踪    执行反馈/数据更新               看执行完成率            信息滞后、不能实时掌握        😟
```

**关键痛点**：信息过载但决策支撑不足——能看到"出了什么问题"，但看不到"该怎么办"。

### 基地管理者旅程

```
阶段        触点                          行为                    痛点                          情绪
─────────────────────────────────────────────────────────────────────────────────────────────────────────
计划排程    电脑端农事计划                 排布当日/本周农事        排程缺乏历史数据参考          😐 → 😕
            人员调度                       分配任务给地块负责人      人员变动大、技能匹配难        😤
过程监控    手机端看执行进度               查看打卡/完成率          实时性差、依赖人工汇报        😟
            设备状态监控                   查看灌溉/气象/水肥       设备告警分散在不同入口        😕
异常处理    预警消息/巡园反馈              处理病虫害/设备故障      异常信息分散、缺乏联动        😤
资源管理    农资申领/库存/采购             审批申请+查库存          库存数据不准、采购周期长      😤
向上汇报    周报/月报                      整理数据上报             手工汇总耗时、数据对不上      😤
复盘总结    经营分析/产量统计              对比计划与实际           缺少归因分析、只有数字        😐 → 😕
```

**关键痛点**：信息孤岛——农事、农资、设备、人员数据分散，需要"一屏掌握"但现状是"到处翻找"。

### 地块负责者旅程

```
阶段        触点                          行为                    痛点                          情绪
─────────────────────────────────────────────────────────────────────────────────────────────────────────
接收任务    手机任务列表                   看今日安排              任务描述不清晰、缺位置信息    😕
执行农事    记农事（拍照+记录）            拍照+选类型+写用量       操作步骤多、需反复打字        😤
            农资使用记录                   记录用了什么多少         选项复杂、品种名称记不住      😕
巡园打卡    GPS打卡+拍照                   定位+拍照+提交           山区GPS不准、网络差提交失败   😤
异常上报    巡园中发现问题                 拍照+描述+上报           描述困难、不知道选什么类别    😕
任务完成    提交完成确认                   标记任务完成             担心漏记影响考核              😟
```

**关键痛点**：操作摩擦——每一步多一次点击，一天多几十次操作，叠加网络不稳定，体验雪崩。

## 三、需求优先级洞察

### 基于频率 × 影响度的需求矩阵

| 优先级 | 需求 | 受益角色 | 频率 | 影响度 | 理由 |
|--------|------|----------|------|--------|------|
| **P0** | 农事任务下达与执行闭环 | 三类全员 | 日频 | ★★★★★ | 系统核心价值链——没有任务流转，系统就是信息展示墙 |
| **P0** | 巡园打卡（GPS+拍照） | 地块负责者 | 日频 | ★★★★★ | 一线最高频操作，体验差则一线拒绝使用，全系统数据断裂 |
| **P0** | 预警消息推送（农事+设备） | 基地管理者/企业管理者 | 日频 | ★★★★☆ | 农业核心风险控制，延迟1小时可能损失数万 |
| **P0** | 农资库存实时查询 | 基地管理者 | 日频 | ★★★★☆ | 库存不准导致停工或浪费，直接影响成本 |
| **P1** | 经营数据看板（大屏+电脑端） | 企业管理者 | 日/周频 | ★★★★☆ | 管理者最直接的价值感知，决定是否持续投入系统 |
| **P1** | 农事记录快速录入（拍照+语音） | 地块负责者 | 日频 | ★★★★☆ | 降低一线操作成本，提高记录完整率 |
| **P1** | 设备状态实时监控 | 基地管理者 | 日频 | ★★★★☆ | 灌溉/水肥设备异常影响产量 |
| **P1** | 农资采购与退货流程 | 基地管理者 | 周频 | ★★★☆☆ | 流程数字化减少纸笔，但紧急程度低于日常执行 |
| **P1** | 模型预测中心（六大农业模型） | 企业管理者/基地管理者 | 日/周频 | ★★★★☆ | 数据驱动决策核心，提升管理科学性与前瞻性 |
| **P2** | 地块绘制与管理 | 基地管理者 | 低频(初始) | ★★★☆☆ | 系统初始化必需，但日常操作频率低 |
| **P2** | 气象/土壤/虫情数据展示 | 基地管理者/企业管理者 | 日频(查看) | ★★★☆☆ | 辅助决策价值大，但数据采集依赖设备稳定性 |
| **P2** | 识病虫/问专家 | 地块负责者 | 周频 | ★★★☆☆ | 场景有价值但使用频率低，可后期迭代 |
| **P2** | 模型快讯与风险摘要（移动端） | 基地管理者/地块负责者 | 日频 | ★★★☆☆ | 模型输出转化为可操作任务和直观查询 |
| **P3** | 角色权限精细管理 | 企业管理者 | 低频 | ★★☆☆☆ | 重要但非紧急，初期可简化 |
| **P3** | 系统备份与字典配置 | 企业管理者 | 极低频 | ★★☆☆☆ | IT运维需求，用户感知弱 |
| **P2** | 模型参数配置 | 系统管理员 | 低频 | ★★☆☆☆ | 模型管理与重训练，保障模型准确性 |
| **P2** | 区块链溯源增强版 | 企业管理者/消费者 | 周频 | ★★★☆☆ | 产品追溯数据上链，提升消费者信任度和品牌价值 |
| **P2** | 无人机巡园 | 基地管理者/植保员 | 周频 | ★★★☆☆ | 高空视角+AI识别，全园无死角覆盖，提升巡园效率 |
| **P2** | VR基地全景展示 | 企业管理者/客户/投资者 | 低频 | ★★★☆☆ | 沉浸式园区浏览，远程参观，营销赋能 |

### 洞察总结

**"一线不用，系统白搭"**——地块负责者的使用体验是整个系统的生死线。如果一线人员拒绝使用或记录不完整，所有上游数据和报表都是空中楼阁。因此，移动端的操作极简化是最高优先级。

## 四、使用场景分析：三端分工

### 场景矩阵

| 场景维度 | 电脑端 | 移动端 | 数据大屏 |
|----------|--------|--------|----------|
| **核心价值** | 深度管理·复杂编排 | 即时执行·现场记录 | 全局态势·汇报展示 |
| **使用场所** | 办公室 | 田间地头/通勤 | 会议室/展厅/办公室 |
| **使用时长** | 单次30min+ | 单次1-5min碎片 | 持续展示/汇报时查看 |
| **网络条件** | 稳定有线 | 不稳定(山区4G/弱信号) | 稳定有线 |
| **操作深度** | 复杂表单、多维报表、计划编排 | 快速记录、一键操作、消息推送 | 只读浏览、不可操作 |

### 各端场景详解

#### 电脑端 — "指挥中心"

| 角色 | 高频场景 | 关键功能 |
|------|----------|----------|
| 企业管理者 | 月度经营分析、预算审批、跨基地对比 | 经营报表、审批流、基地对比 |
| 基地管理者 | 农事计划排程、农资采购审批、周报生成 | 农事排程、库存管理、报表导出 |
| 地块负责者 | 极少使用电脑端 | — |

**设计原则**：信息密度高、操作效率优先、支持批量操作和复杂筛选。

#### 移动端 — "随身工具"

| 角色 | 高频场景 | 关键功能 |
|------|----------|----------|
| 企业管理者 | 查看核心指标、处理审批、接收预警 | 首页仪表盘、审批推送、预警通知 |
| 基地管理者 | 巡园过程监控、农资申请审批、设备状态查看、异常处理 | 消息中心、农事进度、设备状态 |
| 地块负责者 | 查看任务、记农事、巡园打卡、农资记录 | 任务列表、记农事、巡园打卡 |

**设计原则**：操作步骤最少化（核心操作≤3步完成）、大字体大按钮、弱网离线支持、拍照优先于文字输入。

#### 数据大屏 — "态势感知"

| 角色 | 高频场景 | 关键功能 |
|------|----------|----------|
| 企业管理者 | 日常经营监控、汇报展示 | 全局概览、基地/地块分布、产量趋势、预警汇总 |
| 基地管理者 | 基地运营看板 | 人员出勤、农事进度、设备运转、巡园覆盖率 |
| 地块负责者 | 不使用大屏 | — |

**设计原则**：视觉冲击力强、关键指标突出、自动轮播+手动切换、实景图增强代入感。

### 跨端协作场景

**场景1：农事执行闭环**
```
基地管理者（电脑端）排布农事计划
    ↓ 自动下发
地块负责者（移动端）接收任务→执行→记录→提交
    ↓ 自动汇总
基地管理者（手机/电脑端）查看执行进度
    ↓ 自动上卷
企业管理者（大屏/手机端）看全局执行率
```

**场景2：异常预警闭环**
```
设备/气象/虫情监测 → 系统自动预警
    ↓ 推送
基地管理者（手机端）收到预警→研判→派工
    ↓ 下发
地块负责者（手机端）收到紧急任务→现场处理→反馈
    ↓ 上报
企业管理者（手机推送/大屏）看到预警处理进度
```

**场景3：农资流转闭环**
```
地块负责者（手机端）发现农资不足→申领
    ↓ 审批
基地管理者（手机端）审批→查库存
    ↓ 采购（如库存不足）
基地管理者（电脑端）发起采购申请
    ↓ 审批
企业管理者（电脑/手机端）审批大额采购
    ↓ 入库→领用
系统自动更新库存
```

## 五、用户痛点与机会

### 当前农业管理核心痛点

| # | 痛点 | 影响角色 | 现状描述 | 严重度 |
|---|------|----------|----------|--------|
| 1 | **农事排程靠经验、靠微信群** | 基地管理者 | 每天早晨在微信群或白板安排当日工作，变动时逐个电话通知，效率低且容易遗漏 | ★★★★★ |
| 2 | **农事记录断档** | 基地管理者/地块负责者 | 一线人员记录意愿低，记了也是事后补写，数据可信度差；不记录则无法追溯 | ★★★★★ |
| 3 | **库存数据不准** | 基地管理者/企业管理者 | 农资入库出库靠手工台账，盘点困难，常常"账上有但找不到"或"库已空却不知道" | ★★★★☆ |
| 4 | **预警信息分散滞后** | 基地管理者 | 气象预警看天气APP、虫情靠人工巡查、设备故障靠工人电话汇报，没有统一预警入口 | ★★★★☆ |
| 5 | **一线人员操作门槛高** | 地块负责者 | 年龄偏大、智能手机使用不熟练，现有农业APP操作复杂，学不会就不用 | ★★★★☆ |
| 6 | **数据孤岛严重** | 企业管理者 | 产量数据在Excel、农资数据在台账、人员数据在HR系统，无法关联分析 | ★★★☆☆ |
| 7 | **巡园管理粗放** | 基地管理者 | 巡园路线随意、覆盖不全、发现异常后口头传达容易失真，无法量化巡园质量 | ★★★☆☆ |
| 8 | **季节性用工管理混乱** | 基地管理者 | 采摘季临时工大量涌入，技能参差不齐，任务分配和绩效考核困难 | ★★★☆☆ |

### 数字化可解决的机会点

| # | 机会 | 对应痛点 | 解决思路 | 预期价值 |
|---|------|----------|----------|----------|

## 六、关键设计建议

### 1. 移动端"零门槛"策略
- **首屏即任务**：打开APP直接看到"今天我要干什么"，不需要找入口
- **拍照即记录**：农事记录默认拍照为主，AI辅助识别并填入类型和用量
- **离线优先**：弱网环境下可正常记录，联网后自动同步
- **大字大按钮**：核心操作按钮≥48px，字号≥16sp

### 2. 预警"不漏不扰"策略
- **分级推送**：红色（紧急：霜冻/设备故障）→ 电话+弹窗；黄色（注意：虫情异常）→ APP推送；蓝色（提醒：农事到期）→ 列表展示
- **联动派工**：预警→一键创建紧急农事任务→自动分配地块负责人

### 3. 大屏"讲故事"策略
- **实景为中心**：以基地实景图/航拍图为底图，叠加数据图层（产量热力图、设备状态图标、预警标记）
- **时间轴切换**：支持按天/周/月/季/年切换视图，看趋势变化
- **向下钻取**：点击任意基地→地块→具体数据，从宏观到微观

### 4. 数据"流转不留断"策略
- **录入即流转**：一线记录的农事数据自动上卷为基地汇总、企业统计
- **报表自动化**：基地周报、企业月报从数据自动生成，不需人工汇总
- **归因可追溯**：任何数据指标可下钻到原始记录（哪个地块、谁做的、什么时候）
