## 概述

对 `html/dataanlye/` 目录下的两个大屏页面进行完整的静态代码测试，输出详细的测试报告。

## 测试范围

### 测试对象
1. `d:\dev\GitHub\project\pro_orangemodel\html\dataanlye\growth_dashboard.html`（南丰蜜桔生长模型大屏，1955行）
2. `d:\dev\GitHub\project\pro_orangemodel\html\dataanlye\pest_dashboard.html`（南丰蜜桔病虫害模型大屏，2107行）

### 已发现的初步问题（待验证）

**命名不一致问题**：
- 需求说明书（行1391、1417）引用 `growth_big_screen.html` 和 `disaster_big_screen.html`
- 实际文件为 `growth_dashboard.html` 和 `pest_dashboard.html`

**潜在代码问题**（需在测试中验证）：
- `pest_dashboard.html` 中存在 `status-info` CSS类（行1013、1019）但 CSS 中只定义了 `status-completed`、`status-progress`、`status-pending`
- `pest_dashboard.html` 中 `pestCardsData` 变量（行1222-1253）定义后未使用，`renderPestCards` 函数内部重新定义了相同数据
- `pest_dashboard.html` 中存在两个渲染脚本（主脚本 + 行2041自调用函数），可能存在重复渲染
- `pest_dashboard.html` 中 `getSeverityColor` 函数定义但未使用，内部使用 `getSevColor`
- `growth_dashboard.html` 中 `entityData.iot` 数组24项，但 SVG 中 iot 气泡 `data-index` 最大到23，需校验对应关系
- 需求文档说明大屏应有"全屏展示模式"，需检查是否实现

## 测试方法

由于无法在Plan模式执行实际浏览器测试，本次测试采用**静态代码审查 + 需求对照**方式：

### 1. 结构完整性测试
- HTML结构规范性（DOCTYPE、lang、meta、title）
- 外部资源引用（CDN链接、本地CSS/JS路径）
- 主体DOM结构（容器、卡片、图表占位符）
- 模态框/弹窗结构完整性

### 2. 功能完整性测试
对照需求说明书 §2.3（行1385-1439）：
- 生长大屏：6项顶部统计 + 4个图表 + 数据表格 + 地块详情弹窗 + 全屏模式
- 病虫害大屏：6项顶部统计 + 4个图表 + 预警列表 + 预警详情弹窗 + 全屏模式

### 3. JavaScript功能测试
- ECharts 实例初始化（所有图表ID是否对应DOM元素）
- 函数定义完整性（openModal、closeModal、openPopup、closePopup、switchTab等）
- 事件监听器绑定（onclick、addEventListener）
- 数据对象完整性（entityData、scrollingEntities、pestCardsData、scatterData、nanfengGeoJson）
- 变量作用域与重复定义检查
- 数据索引与SVG元素对应关系
- 滚动动画、KPI数字动画、resize事件处理

### 4. 数据准确性测试
- KPI数值与需求文档一致性
- 乡镇名称与南丰县实际乡镇一致性
- 蜜桔品种数据（7个品种）
- 病虫害种类数量（8种病害、10种虫害）
- 物候期数据（6个阶段）
- 涉农主体数据（service/enterprise/cooperative/demonstration/largegrower/iot）
- 日期数据（是否对齐2026年7月）

### 5. CSS样式测试
- 设计系统变量定义（dashboard-design-system.css）
- 内联样式与设计系统一致性
- 响应式断点（@media 1100px、700px）
- 类名是否在CSS中有定义（重点检查 `status-info`）
- 颜色规范（主色系 #2b6e3c）

### 6. 交互体验测试
- KPI卡片点击弹窗（openModal 8种类型）
- 地图气泡点击弹窗（openPopup）
- 滚动表格Tab切换（switchTab、filterPestCards）
- 模态框关闭（closeModal、点击遮罩、X按钮）
- 滚动动画悬停暂停
- 链接跳转（病虫害模型↔生长模型、电脑端、移动端）

### 7. 性能/资源测试
- ECharts 实例数量与内存释放
- CDN依赖加载（ECharts、Font Awesome）
- 图片资源使用（检查是否使用文生图API）
- 动画性能（KPI数字动画、滚动动画、脉冲效果）

### 8. 一致性测试
- 两个大屏页面之间的视觉风格一致性
- 与设计系统CSS的符合度
- 主体数据在 KPI / 弹窗 / 图表 中的数值一致性

## 假设与决策

1. **测试方法**：采用静态代码审查，不执行浏览器测试（受Plan模式限制）
2. **测试基准**：以需求说明书 §2.3 和 project_memory 中的硬约束为基准
3. **缺陷分级**：
   - 严重：功能无法使用、数据错误、与需求严重不符
   - 一般：样式问题、命名不一致、未使用变量
   - 轻微：代码风格、注释缺失、可优化项
4. **报告语言**：中文
5. **报告格式**：Markdown，包含表格、代码引用、可点击文件链接
