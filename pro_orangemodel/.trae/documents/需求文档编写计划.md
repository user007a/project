## 三、关键差异对比（需求说明书 vs HTML实现）

以下列出需求说明书与HTML实际实现的主要差异，需求文档将以HTML实现为准：

### 3.1 后台菜单结构差异

| 一级菜单 | 需求说明书二级 | HTML实际二级 | 说明 |
|----------|-------------|-------------|------|
| 模型管理 | 生长模型、病虫害防控模型、病害数据库、虫害数据库、灾害数据库 | 生长模型、病虫害模型、**气象灾害模型**、病害数据库、虫害数据库、灾害数据库 | HTML多了"气象灾害模型" |
| 规则管理 | 预警规则、**内容设置**、**流程设置**、发送模板 | 预警规则、发送模板、（内容设置/流程设置作为发送模板的子功能弹窗） | HTML菜单仅2项，内容设置和流程设置作为弹窗存在 |
| 运行监控 | 长势研判、品质预测、**农事推荐**、**病虫害趋势研判**、模型日志 | 长势研判、品质预测、**产量预测**、**气象监控**、系统日志 | HTML用产量预测+气象监控替代了农事推荐+病虫害趋势研判 |
| 系统管理 | 用户管理、**系统日志**、**数据同步**、**小程序设置** | 用户管理、**角色管理**、**系统配置** | HTML用角色管理+系统配置替代了系统日志+数据同步+小程序设置 |

### 3.2 微信小程序模块差异

| 维度 | 需求说明书 | HTML实现 |
|------|-----------|---------|
| 底部导航 | 首页、数据、病虫害、资讯、我的 | 首页、监测、AI、病虫害、我的 |
| 导航命名 | "数据" | "监测" |
| 首页快捷服务 | 未详细定义顺序 | 8个快捷入口（AI识别→mb_disease_ai, AI农事→mb_ai, 环境监测→mb_data_monitor, 我的果园→mb_data_orchard, 病虫害库→mb_disease_knowledge, 数据录入→mb_data_input, 市场信息→mb_market, 农技知识→mb_news） |
| 新增页面 | 无 | mb_ai.html（AI助手"小果"）、mb_market.html（市场信息/价格指数） |
| 市场信息 | 未提及 | 仅保留柑桔品类，含价格指数、趋势图、价格列表 |
| AI助手 | 未提及 | 问答/历史双Tab，6分类筛选，热门问题，AI识别入口 |
| 病虫害二级 | AI智能识别、病虫害知识库、预警上报 | AI智能识别、病虫害知识库、预警上报（一致） |
| 监测二级 | 我的果园、数据录入、设备监测、建议生成 | 我的果园、数据上报、设备监测、智能建议（一致） |
| 我的二级 | 个人中心、服务记录、设置 | 个人中心、服务记录、设置（HTML多了详情页） |

### 3.3 数据大屏差异

需求说明书定义了两块大屏的展示维度，HTML实现与需求基本一致，但细节上有补充：

| 大屏 | 需求说明书展示维度 | HTML实际内容 |

| 生长模型大屏 | 8个维度 | 8个KPI卡片+SVG地图气泡+滚动数据表+6个ECharts图表+弹窗详情 |
| 病虫害大屏 | 10个维度 | 8个KPI卡片+热力地图+滚动数据表+6个ECharts图表+弹窗详情 |

### 3.4 数据表格差异

很多页面的数据量、弹窗功能与需求说明书描述存在差异，以HTML实现为准。
